# חבילות דרייברים — מ-driver pack של היצרן לשרת

**למי זה:** מפעיל שמשחזר אימג' Windows שנקלט מדגם אחד על דגם אחר, ורוצה
שהמכונה תעלה עם דרייבר רשת/אחסון. המנגנון עצמו (מה הסוכן מניח, איפה, ומה
Windows עושה בעלייה הראשונה) מתואר ב-[`interfaces.md`](interfaces.md) §17;
המסמך הזה הוא **איך מכינים חבילה**, בארבעה צעדים.

> **מה זה לא עושה:** בקר אחסון שבלעדיו Windows לא עולה כלל מכוסה רק
> כשהדרייבר שלו **מובנה ב-Windows** — הסוכן הופך את `storahci`/`stornvme`
> של הדיסק שנכתב ל-boot-start (‏#1331, ‏`interfaces.md` §17 צעד 5א). בקר
> שצריך דרייבר של היצרן כדי לעלות (Intel VMD/RST) — **עדיין לא**, גם אם
> הוא בחבילה. "הונח" אינו "הותקן" — הסוכן מדווח מה הניח, לא מה
> Windows התקין. **ואף חבילה לא אומתה עדיין על ברזל** (‏#720 פתוח על זה).
> לפני שיכפול או שחזור, יש להגדיר את מחשב היעד ל־AHCI לפי
> [צ'קליסט מצב SATA](server-install.md#לפני-שיכפול-או-שחזור--מצב-sata-במחשב-היעד).

## 1. להוריד את ה-driver pack של הדגם

כל היצרנים מפרסמים חבילת דרייברים לדגם, מיועדת ל-SCCM/MDT — קובץ CAB או
EXE שנפרש לתיקייה:

| יצרן | איפה | פורמט |
|---|---|---|
| HP | HP Client Management Solutions → "Driver Packs" (לפי דגם ו-Windows) | `sp<N>.exe` — להריץ ולפרוש לתיקייה (או `7z x`) |
| Lenovo | Lenovo Support → "SCCM Package" לדגם | `.exe` שנפרש לתיקייה |
| Dell | Dell Command | Deploy Driver Packs | `.cab` |

חבילה לדגם **ולגרסת Windows** של האימג' (10/11). הכלי מקבל **CAB או
תיקייה**; EXE של HP/Lenovo פורשים קודם (הפעלה כפולה או `7z x`), ואת
התיקייה מוסרים לכלי.

## 2. לדעת מה המכונה מדווחת

בקונסולה, **כרטיס המכונה** מציג את מה שהסוכן דיווח ב-hello: יצרן
(`sys_vendor`), דגם (`product_name` / `product_version`) ובקרי הרשת
והאחסון (‏PCI). זה מה שהחבילה תתאים אליו — **מעתיקים משם, לא ממדבקה**:
אצל Lenovo השם הידידותי ("ThinkCentre M720q") יושב ב-`product_version`
ו-`product_name` הוא קוד ("10SQS0AK00"); כל אחד מהשניים תקף.

## 3. לבנות את החבילה

על תחנת Windows (‏Python 3.12) או על השרת (דביאן):

```
python tools/drivers/build-package.py sp150000\ --vendor HP --model "HP EliteDesk 800 G6 Desktop Mini PC" --version 2.1
python tools/drivers/build-package.py drivers.cab --vendor LENOVO --model "ThinkCentre M720q" --out m720q.tar
```

מה הכלי עושה, ומה הוא מסרב לעשות:

- **פורש CAB** — ‏`expand.exe` בווינדוס, ‏`cabextract` או `7z` בלינוקס
  (`apt install cabextract`). בלי אחד מהם — סירוב בשמו, לא "0 קבצים".
  ‏`expand.exe` **מעתיק** קובץ שאינו CAB במקום לפרוש אותו ויוצא 0 — הכלי
  תופס את זה ומסרב.
- **סורק כל `*.inf`** למזהי `PCI\VEN_xxxx&DEV_xxxx`, ורק מ-INF של רשת
  ואחסון (‏`Class=Net` / `HDC` / `SCSIAdapter`) — אלה שני סוגי הבקרים
  היחידים שהסוכן מדווח במלאי, ומזהה של כרטיס מסך לא יתאים לעולם. הסיכום
  אומר כמה INF דולגו ולמה.
- **כותב `manifest.json`** עם שני כללים: דגם (`--vendor` + `--model`)
  ו-`pci_any` (המכונה מחזיקה **אחד** מהבקרים). בלי `--vendor` אין כלל
  דגם — הסיכום אומר זאת, וההתאמה היא לפי בקרים בלבד.
- **‏sha256 לכל קובץ**, ו-tar בשם החבילה (`--name`, או נגזר מ-vendor+model,
  ‏ASCII בלבד — זה שם התיקייה שתיכתב ל-`\ImageSrv\Drivers\` על הדיסק).
- **מסרב** על: יותר מ-2,000 קבצים או 512 מזהים (לפצל — רשת ואחסון בנפרד),
  נתיב לא-ASCII, ‏`manifest.json` שכבר קיים בתיקייה, ואין על מה להתאים.

הסיכום שמודפס — דגם, INF, מזהי PCI, קבצים, גודל, ‏sha256 של ה-tar — הוא
מה שמשווים מול דף הדרייברים אחרי ההעלאה.

## 4. להעלות ולראות שהיא תואמת

**דף "דרייברים" → ייבוא חבילה** (admin; ה-API הוא
`POST /api/console/drivers/upload` עם ה-tar כגוף, מאחורי ה-cookie של
הקונסולה). השרת מאמת את כל ה-sha256 **לפני** שהחבילה נכנסת, ודוחה בשמו כל קובץ
חסר/עודף/שונה. אחרי הכניסה הדף מציג לכל חבילה **"מתאים ל-N מכונות"** —
לפי המלאי האחרון שכל מכונה רשומה דיווחה. **זו הבדיקה:** אם המכונה שבשבילה
הורדת את החבילה אינה ברשימה, הדגם שהקלדת אינו מה שהיא מדווחת (ראה צעד 2)
או שאף בקר שלה אינו ב-INF-ים. חבילה שתואמת מוצגת בסיום השחזור כ-`staged`
ליד המחשב.

חבילה היא **בלתי-משתנה**: תיקון = מחיקה (הקלדת השם) ובנייה מחדש.

# ImageCtl — מסמך אפיון

**גרסה 1.2 של המסמך** · ספטמבר 2026 · מתאר את **v1** כפי שנמסר
מבני הנתונים — ב-`docs/interfaces.md` (מקור האמת). מצב הבדיקות — במסירה
האחרונה (`docs/handoff-*.md`). מבוא והפעלה — `README.md`.

מסמך זה אומר **מה המערכת עושה, למה, ובאילו אילוצים** — במצבה הנוכחי, לא
כפי שדמיינו אותה באוגוסט. גרסה 1.1 תיארה שרת אחד, כיתות כתרחיש מרכזי
ו"הכול HTTP"; ביקורת R56 מצאה 18 סעיפים מיושנים, ולכן זו גרסה חדשה של
**המסמך** — המוצר נשאר v1. סעיפים שעברו ל-v2 (כיתות) מכונסים בנספח ה'.

# חלק א' — היקף

## 1. מה ב-v1 ומה לא

| | v1 (המסירה) | v1.1 | v1.2 |
|---|---|---|---|
| **כן** | מחשב בנייה, מחשבי שיכפול, שרתים (ראשי + משניים), קליטה, הפצה לחדר, שחזור עצמי במחשב הבנייה, אחסון, אבטחה, התקנה מ-ISO, עדכון מהקונסולה | ארגז הכלים לאיש IT (מוקאפ לכל כלי לפני בנייה) | כיתות: תחנת תלמיד, הפצה לכיתה, החלפה בין קורסים |
| **בקוד** | הכול למטה | הקטלוג קיים, אינו מוצג (`menu_tools=0`) | המנגנון קיים ומוסתר: `capabilities.classrooms=false` (#1081) |

**הכרעת נדב (17–18/09):** v1 = בנייה, שיכפול ושרתים בלבד. הכיתות **אינן מוצגות
כלל** ב-v1 — לא בקונסולה, לא בתפריט האתחול. כל מה שמניח תחנת תלמיד
נמצא בנספח ה' ואינו הבטחת מסירה.

## 2. המצב לפני, ומה המערכת משנה

כל אימג' היה SSD פיזי; שיכפול בקסקדה (`dd`, 1→2→4→8) עד ~30 כוננים לכיתה,
עד 5 כיתות בשבוע. עכשיו כל אימג' הוא **קובץ על השרת**, ושידור מולטיקאסט
אחד כותב לכל המגירות בחדר במקביל: הזמן ל-36 מגירות הוא הזמן של אחת.
נמדד: ‏office365 (‏20GB) — ‏≈13 דק' ל-6 דיסקים ב-3 מכונות (12/09); זרם
של 933 שניות עם 0% איבוד (10/09). ‏~20 כונני מקור מתפנים למלאי, גרסה
נוספת היא קובץ ולא כונן, ושם המחשב נכתב אוטומטית.

**אילוץ מפשט:** זרם מולטיקאסט אחד פעיל בכל רגע לשרת.

# חלק ב' — ארכיטקטורה

## 3. הרכיבים

```
   עמדת IT (דפדפן, HTTPS 8081)
        │
   ┌────┴─────────────────────────────── שרת ראשי (ת"א) ───┐
   │ קונסולה 8081 · API הסוכן 8080                          │
   │ DHCP/TFTP של וילן ההפצה · dnsmasq · nftables · DCUI  │
   │ ספריית אימג'ים (דיסק = מקור האמת) · sqlite לשאר      │
   └───────────────┬──────────────────────────┬────────────┘
        וילן ההפצה │                          │ 8443 mTLS (הראשי יוזם; #1310)
   ┌───────────────┴──────┐           ┌───────┴────────────────┐
   │ מחשב בנייה (GUI)     │           │ שרת משני (חיפה)        │
   │ מחשבי שיכפול (GUI)   │           │ אותו קוד, אותה קונסולה │
   └──────────────────────┘           │ הפצה לחדר שלו בלבד     │
                                      └────────────────────────┘
```

| רכיב | מה הוא | איפה מתועד |
|---|---|---|
| **שרת ראשי** | דביאן 13 + ImageCtl; הקונסולה, ה-API של הסוכן, DHCP/TFTP לוילן ההפצה, ספריית האימג'ים | `docs/server-install.md`, `install/` |
| **שרת משני** | אותה התקנה בתפקיד `secondary`, מצומד לראשי (mTLS, 8443). הראשי **תמיד** היוזם: דוחף אימג'ים (push) ומושך (pull, #1070) — חוץ מ"אתה שם?" אחד של מתקין המשני (#1310). המשני מפיץ רק לחדר שלו | `interfaces.md` — Storage Nodes |
| **מחשב בנייה** | תחנת עבודה שמתקינים עליה מערכת; עולה ב-PXE לגואי נייטיבי (Pango/fbdev, עברית RTL): קליטה, הפצה לחדר, שחזור לדיסק שלו, הפצה ישירה מהדיסק (#715) | `native-gui/`, `docs/gui-*.md` |
| **מחשבי שיכפול** | 2–3 מגירות; עולים ב-PXE, מדווחים מגירות ובריאות SMART, ממתינים לסבב; מסך התקדמות לכל דיסק (#654) | `agent/`, `docs/agent.md` |
| **הסוכן** | initramfs אחד לכל התפקידים — POSIX sh, ‏`fanout.c`, ‏`partclone`, ‏`udpcast`. **אין התקנה על אף מחשב** | `agent/`, `tools/build_initramfs.sh` |
| **DCUI** | מסך השרת עצמו (tty1): כתובת, תעודה, מצב השירותים; F2 להגדרות עם סיסמת המנהל, F12 כיבוי/אתחול | `server/dcui/` |

**עיקרון:** הסוכן חסר-מצב ואינו יודע דבר לפני ה-`hello`; ההרשאה, הזהות
וההחלטה יושבים בשרת. שורת הפקודה של הקרנל נקייה מפרטי משימה
(`imagectl.server` ו-`imagectl.mode=recovery` בלבד).

## 4. עובדות שקובעות תכנון

| | מצב | השלכה |

# חלק ג' — רשת

## 5. שלושה וילנים לאתר

| וילן | מי | מה עובר |
|---|---|---|
| **הפצה** (`DEPLOY`) | כרטיס ההפצה של השרת, מחשב הבנייה, מחשבי השיכפול, סוויץ' משלו | DHCP/TFTP של ImageCtl, ‏API הסוכן (8080), מולטיקאסט (9000–9001), מוניטור (5900). **אינו מנותב** |
| **שרתים/ניהול** (`SERVERS`) | כרטיס הניהול של כל שרת, בכתובת מ-DHCP של המכללה או סטטית (#1088) | הקונסולה (**HTTPS 8081**), בין-שרתי (8443), NTP, ‏443 ל-github בזמן עדכון בלבד |
| **כיתות** (`CLASS`) | תחנות התלמידים | **סגור לשרת ב-v1** |

**רשת ההפצה מוגדרת מהקונסולה אחרי ההתקנה**, לא בהתקנה: המתקין שואל רק על
כרטיס הניהול; "הגדר את רשת ההפצה" הוא הפריט היחיד במסך הבריאות של שרת
טרי (#1148). הדלקת DHCP היא ההגדרה המסוכנת ביותר במערכת — כבוי כברירת
מחדל, אישור עם שם הכרטיס, זיהוי DHCP קיים על הכרטיס (#53), ואזהרה
מפורשת על כרטיס הניהול.

**חומת האש בשרת** (`install/nftables-rules.sh`): socket לכל תפקיד על הכרטיס
שלו; **אין SSH על שרת הייצור** (#1148), ואין SSH במוצר בכלל (#1266).
**חומת האש של המכללה:** `install/firewall-rules.md` — כללי כתובת/פורט
בלבד, בלי בדיקת נתיבי HTTP; בין האתרים רק 8443 מהראשי למשני, ו-8443 מהמשני
לראשי ל"אתה שם?" בלבד (#1310).

## 6. IGMP ורוחב פס

בלי querier פעיל טבלת החברות במתג פוקעת אחרי 125–260 שניות והזרם נופל
באמצע. **נדרש:** snooping על כל מתג בנתיב, querier אחד לוילן, ‏v2 עקבי.
‏1G = ‏~110MB/s לזרם — כל כונן נכתב איטי מ-`dd` מקומי, והרווח כולו
בהקבלה; ‏10GbE בחדר השיכפולים מעלה את הזרם ל-~1GB/s. נמדד במעבדה 106MB/s
בלי צוואר בקבוק (17/09); ‏Dynamic Memory ב-VM היה הצוואר, לא הרשת.

# חלק ד' — שרשרת האתחול

## 7. Secure Boot והתפריט הדינמי

```
קושחה → shim (Microsoft) → GRUB (דביאן) → קרנל (הפצה) → initramfs (חופשי)
```
עדכון הסוכן = החלפת `initrd.img` בשרת (firstboot בונה אותו מהקוד המותקן).
‏GRUB מושך `configfile (http,<server>)/boot/menu?mac=<MAC>` והשרת מייצר
תפריט **לפי ה-MAC**: התפקיד נגזר מהקבוצה, לא משדה. שרשרת האתחול
מאומתת בהתקנה (`verify-boot-payload.sh`: ‏vmlinuz, ‏initrd.img,
‏initrd.img.gui, גדלים מלאים — #1161).

## 8. עקרון הבטיחות

**ברירת המחדל היא תמיד אתחול מהדיסק המקומי.** MAC לא רשום, סכימה זרה,
שרת שקט, סוג משימה לא מוכר — כולם מסתיימים בדיסק המקומי **מיד**
(`timeout=0`, ערך יחיד בקובץ, בלי מסך). שרת כבוי = ‏PXE נכשל בקושחה
והתחנה עולה מהדיסק בלי לעבור בתפריט כלל.

**מחשב רשום** (בנייה/שיכפול) עולה **ישר ל-ImageCtl, אוטומטית** — בלי מסך
בחירה, בלי ESC ובלי טיימר (#641, הכרעת נדב 10/09, היפוך #140); בחירת
הדיסק המקומי היא **בתוך** מסך ImageCtl. מחשב שיכפול עולה ישר לסוכן (#17).

**האתחול המקומי מנסה את כל הנתיבים** (`bootmgfw.efi`, ‏`/EFI/<distro>/grubx64.efi`,
‏`/EFI/Boot/bootx64.efi`), ומחשב שאין לו bootloader אומר זאת.

## 9. זהות מכונה

זהות = MAC מוצהר **+** כתובת מקור שתואמת את חכירת ה-DHCP של אותו MAC
(#855, ‏`interfaces.md` §21). וילן ההפצה אינו גבול אמון (#702): במכללה
לומדים סייבר, ומכונה עם Kali תנסה `hello` בשם מחשב הבנייה. "אין חכירה" =
לא ניתן לבדוק = **סירוב**; אותו שומר על כל נתיבי הסוכן (#997), ועל
`manifest`/`files` בכיוון ההפוך (כתובת → חכירה → מכונה רשומה). זיוף MAC
ברמת הכבל = port-security בסוויץ', מחוץ להיקף.

# חלק ה' — האימג'ים והאחסון

## 10. מבנה

אימג' = תיקייה עם `manifest.json` וקובץ `partclone | zstd` לכל מחיצה.
**הדיסק הוא מקור האמת** — ‏`git`, גיבוי והעברה בין שרתים הם העתקת תיקייה;
‏sqlite מחזיק רק מה שאין לו ייצוג כקבצים. ‏partclone קורא בלוקים תפוסים
בלבד: כונן 256 עם ~80GB בשימוש ≈ 50–60GB דחוס.

**‏sha256 קצה-לקצה:** אימות לפני שהאימג' נכנס לספרייה (קליטה/העלאה) —
פגום נתפס שם, לא מול חדר. במקבל: `sha256` על הבייטים הדחוסים כפי
שהתקבלו; אי-התאמה = היעד נכשל בגלוי.

## 11. מידה, מערכת, כיווץ

- **מידה** לכל אימג' (256/500), נגזרת מכונן המקור — **תווית תצוגה בלבד**.
  אם אימג' מתאים לדיסק מכריע **רק הגודל האמיתי** (‏`required_bytes` ועוד
  המינימום הפנוי, #1354) מול הדיסק שנבחר — אותה הכרעה בקונסולה, במסך
  המשכפל, במחשב הבנייה וברשימה שהסוכן מציג (‏#1863, הכרעת נדב 20/10).
  לכל היותר מחיצה אחת ניתנת להרחבה, והיא האחרונה; ‏`sgdisk -e` בכל שחזור.
- **כיווץ בקליטה** (#929): כל מחיצת NTFS מכווצת לתפוס + שוליים לפני
  הזרם ומורחבת חזרה אחריו; המניפסט מתאר את הפריסה המכווצת. אומת
  קצה-לקצה 17/09 (500→146GB, שוחזר ל-256, ווינדוס עלה).
- **מערכת** (`windows`/`linux`) נגזרת מסוג המחיצות: כלי שחזור, הרחבה
  (`ntfsresize`/`resize2fs`/`btrfs`/`xfs_growfs` #667), כתיבת שם (רג'יסטרי
  offline דרך hivex / ‏`/etc/hostname`). ‏swap נוצר מחדש, לא נשמר.
- **שערים לפני קליטה** (קריאה בלבד): מהובר/Fast Startup (#651 —
  `ntfs-3g.probe`), ‏BitLocker (#671 — כותרת `-FVE-FS-`), ‏`used_bytes` לא
  ידוע = מציגים מונה וקצב, לא אחוז (#408).

## 12. הזרם

**שידור אחד = קובץ מחיצה אחד, בייט-בייט.** הסוכן מושך מניפסט ב-HTTP,
כותב GPT מהמניפסט (**הטבלה לעולם לא בזרם**), מקבל שידור לכל מחיצה
בסדר, מרחיב, כותב שם. המקבל מפרק: `udp-receiver | zstd -d | partclone`.
‏`udp-sender` עם תקרות: ‏`--max-wait`, ‏`--start-timeout` (#341),
‏`--retries-until-drop` (#437), ‏`--max-bitrate` (#24); "Starting transfer"
בלוג הוא הראיה שמישהו הצטרף (#438) — קוד 0 לבדו אינו.

**מגירות מרובות** (`agent/fanout.c`): הזרם מתקבל פעם אחת ומשוכפל לתור
נפרד לכל יעד. יעד איטי מעכב את הזרם (לחץ-גב, #660) ואינו מפונה; יעד
שמלא **ולא התקדם בכתיבה** במשך ‏`STALL_EVICT_MS` (150 שניות, #674) נכשל
בגלוי והשאר ממשיכים. ויעד שמחזיק את קריאת הזרם (stdin של fanout) ‏45 שניות
ברצף בזמן שליעד אחר יש מקום — כלומר פינה פחות מקריאה אחת (‏1MiB, ‏~23KB/s)
— נכשל גם הוא (‏`BLOCK_EVICT_MS`, #1796): בזמן הזה ‏udp-receiver אינו עונה,
ו-udp-sender מנתק את המכונה כולה אחרי ~190 שניות. **אסור לזרוק בלוק בשקט.** יוניקאסט (שחזור עצמי, משיכה)
= אותו קובץ, ‏`GET` במקום `udp-receiver`.

## 13. אחסון

- **מיקומי אחסון** (`storage_locations`): מקומי, NFS, SMB, iSCSI —
  מוגדרים ומחוברים מהקונסולה; הספרייה יכולה לשבת על כל אחד.
- **שרתים משניים** (`storage_nodes`): צימוד mTLS מהראשי, דחיפה ומשיכה של
  אימג'ים, מוניטור למכונה בסניף דרך המשני.
- **גיבוי ושחזור של השרת** (#1128): מעוצב (R41), טרם נבנה — ‏`.backup`
  ל-sqlite, ‏`verify-images`, כפתור "הורד גיבוי הגדרות".

## 17. הקונסולה

דפדפן, עברית RTL, מצב בהיר ברירת מחדל, סרגל ומסגרת קבועים (עיצוב לפי

דורש טיפול), **סבב הפצה** (חדר המשכפלים — גריד מכונות × מגירות, SMART,
‏WoL, גלים), **מלאי** (אימג'ים בתיקיות, מחשבים בקבוצות עם הדבקה מרובה/CSV,
‏MAC לא רשום), **תשתית** (בריאות, אחסון, רשת/DHCP, מוניטור, דרייברים,
סניפים), **ניהול** (משתמשים, MFA, יומן, הגדרות, **עדכון**). כללי הנראות
ראשי/משני — הכרעות 17/09; במשני אותו עץ (#1179, בהמשך).

**מסך הבריאות:** בדיקות שתלויות ברשת ההפצה הן "לא ישים" עד שהיא מוגדרת;
אין שורות SSH (‏#1266); "לא הצלחנו לבדוק" הוא **אדום**, לא ירוק (עיקרון 5).

**עדכון מהקונסולה** (#748): בדיקה מול הריפו הציבורי, החלה של תג
(‏`git fetch/checkout` מחוץ לסנדבוקס של השרת, #1193), הפעלה מחדש,
ו-rollback לגרסה הקודמת (#1131). ‏443 החוצה נפתח בחומת האש לזמן העדכון.

## 18. הגואי הנייטיבי (מחשב הבנייה ומחשבי השיכפול)

מסך גרפי (Pango/cairo על fbdev/drm, עברית RTL, בהיר/כהה) שהסוכן מריץ
בתוך ה-initramfs; הלוגו של המכללה מהקונסולה בכותרת (#1168). מחשב הבנייה:
כניסה → תפריט (קליטה / הפצה לחדר / שחזור לדיסק זה / הפצה ישירה) →
מסכי התקדמות עם מונה, אחוז וקצב. מחשב שיכפול: "ממתין לסבב" עם המגירות
ובריאות SMART, ואז התקדמות **לדיסק 1/2/3** (לפי פורט SATA, לא `sd*`);
שאלת SMART (החלף/כתוב בכל זאת/דלג) עם nonce; ‏done עם אזהרה בכתום (#943).
מחשב שממתין לאיש נכבה אחרי 5 דקות עם ספירה לאחור על המסך; **מסך כשל
נשאר דולק** (#434). מוניטור מרחוק (RFB דרך השרת, #690) לצפייה ושליטה.

## 19. ההתקנה — ISO ואשף על מסך השרת

‏`tools/iso/build-iso.sh` בונה ISO מהריפו הציבורי: דביאן 13 + ImageCtl
offline (pool מאומת לפי `Package`, #1162), UEFI/Secure Boot + BIOS,
והמתקין **החי** שלנו (#1190): ה-ISO עולה ישר לאשף גרפי על מסך השרת
(כמו ESXi) — **דיסק** (טבלה, "יימחק", "אני מבין", אתחול מקומי) → **תפקיד**
(ראשי/משני) → **כתובת השרת** (כרטיס הניהול, DHCP/סטטי) → **שם השרת** →
**חשבון ניהול** (שם משתמש נבחר, סיסמה עם "הצג") → סיכום → החלה →
"הסר את מדיית ההתקנה והפעל מחדש". באתחול הראשון `firstboot` בונה
את ה-initrd, מריץ את `setup-boot-server` מהתשובות, מאמת את המטען, ומעלה
את ה-**DCUI**. אין debian-installer, אין preseed, אין אשף בדפדפן במסלול
הזה (האשף בדפדפן נשאר לשרת בלי מסך). ‏`.git` של הציבורי נארז בעץ —
כפתור העדכון עובד מיד.
